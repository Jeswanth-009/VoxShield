# VoxShield: corrective audit, September 2026

## Status and corrections to earlier conclusions

The old assertion that 12,259 parameters had reached their capacity limit was
not supported by the available experiments. The code and benchmark data had
confounding defects. Fixing those defects is necessary before attributing the
remaining quality gap to architecture size. No model is certified for defence
communications, and none has demonstrated the full SIH targets on all domains.

## Confirmed defects and fixes

1. **Repeated mixtures with persistent workers.** The original dataset used a
   plain integer epoch. Worker Dataset copies did not observe main-process
   set_epoch updates. A shared-memory scalar now propagates epochs, including
   Windows spawn. A real persistent-worker test checks changed mixtures and
   deterministic replay. A separate sampler RNG now decouples shuffle order
   from worker creation. Bitwise CUDA reproducibility is not promised.
2. **Untrained high-pass output conditioning.** Every enhanced file passed
   through y[n]=x[n]-x[n-1]+0.995*y[n-1], although training targets did not.
   This introduces phase/amplitude error even for a clean identity output.
   Default conditioning now sanitizes and bounds amplitude without this filter.
   The DC blocker remains opt-in for measured hardware needs.
3. **Cross-file state leakage.** Stream reset did not reset the DC blocker or
   health status. It now resets both, as well as recurrent and overlap buffers.
4. **Invalid frozen noisy examples.** Old val_v4 contains five rows whose noisy
   and clean PCM audio are identical despite noisy category labels: 000027,
   000083, 000331, 000337, 000433. The old manifests/audio remain unchanged.
   New generation rejects silent source mixtures, recovers active noise crops,
   and refuses to overwrite an existing frozen manifest. Evaluation records
   invalid pairs and fails the engineering gate instead of dropping them.
5. **No military validation.** manifests_v4 contains MAD training/test data but
   zero MAD validation data. Weighting validation could not fix absent files.
   manifests_v5 reserves catalog recording groups from the official MAD training
   pool: 3,997 train, 1,658 validation, 830 original test. Requested hash fraction
   is 15% of group IDs; actual file fraction differs due to unequal group sizes.
   VCTK speaker/RIR/ESC/UAV partitions remain unchanged. V5 requires MAD validation
   coverage at loader startup. Catalog grouping is not proof of acquisition-
   session or acoustic-content independence; additional source metadata is needed.
6. **Unrepresentative first-file sampling.** New fixed generation shuffles clean
   source rows with a documented seed and records clean source paths. Old fixed
   generation used the first sorted source rows, making small subsets vulnerable
   to speaker/file-order bias.
7. **Missing PESQ and hidden scoring failure.** Official pesq 0.0.4 is compiled,
   installed in C:/anc/.venv, and checked against upstream known WB/NB values.
   --require-pesq fails on absent/invalid scores; strict gates require complete
   PESQ coverage. Optional scoring now reports errors instead of silently hiding them.

## Model decision and experiments

The user's current hardware has no synchronized noise-reference microphone.
The v4 model expects that channel. Synthetic reference results cannot be claimed
for laptop mono input or two arbitrary laptop-array channels.

V5 mono uses the complete official GTCRN, initialized from the supplied upstream
DNS3 checkpoint, with the new manifests. It has 23,669 trainable parameters;
upstream's approximately 48.2K count also includes fixed ERB parameters. This is
different from v4's custom 12,259-trainable-parameter dual model. V5 mono has
16 kHz input, 512-point STFT and 256-sample hop; it needs no reference file.

The recipe uses power-compressed magnitude and complex losses plus SI-SNR, SNR,
waveform L1, clean identity and speech retention. BatchNorm pretrained statistics
are frozen. Three short pilot epochs were run before the full 20-epoch recipe.
Pilot metrics are not evidence that the final targets are met. A separate failed
v4 recovery attempt was stopped on finding absent military validation.

V4 remains available for the future synchronized two-microphone experiment.
Dry/wet ablations compare 0.90 versus 1.00 on identical manifests; greater noise
rejection must still be checked against clean preservation and speech deletion.

## Research basis

- Official GTCRN architecture, pretrained models, parameter-count caveat and
  stateful inference: https://github.com/Xiaobin-Rong/gtcrn
- H-GTCRN offers a researched IVA-assisted dual-channel design, but its additional
  separation front end needs a real microphone geometry and streaming validation:
  https://github.com/Max1Wz/H-GTCRN
- DeepFilterNet is a 48 kHz deep-filtering alternative; it is not a drop-in
  replacement for this 16 kHz model/state interface:
  https://github.com/Rikorose/DeepFilterNet
- UL-UNAS provides another lightweight architecture with upstream streaming code;
  its published results do not establish superiority on these defence mixtures:
  https://github.com/Xiaobin-Rong/ul-unas
- Worker dataset instances persist when persistent_workers is enabled:
  https://docs.pytorch.org/docs/stable/data.html
- PESQ wrapper requirements and known reference values:
  https://github.com/ludlows/PESQ

These sources support investigating alternatives, not stacking arbitrary Wiener,
IVA, neural, NLMS and transient-gating stages without controlled evidence.

## PESQ installation evidence and reproduction

The default MSVC build failed because MSVC was absent. The existing MSYS2 UCRT
GCC compiler built the official PyPI source. Only obsolete setup_requires was
removed from its build metadata; scoring C/Cython source was unchanged.

- Upstream source SHA256: b724b28f73fb638522982bd68e8c3c0957e2f45210639a460233b17aa7fc890b
- Known sample WB PESQ: 1.0832337141036987 (exact match).
- Known sample NB PESQ: 1.6072081327438354 (exact match).
- Wheel: external/pesq-build/pesq-0.0.4-cp312-cp312-win_amd64.whl.
- This wheel is for Windows x64 CPython 3.12 only. Do not copy it to Raspberry Pi.

```powershell
cd C:\anc
& .\.venv\Scripts\python.exe -m pip install --no-index --no-deps .\external\pesq-build\pesq-0.0.4-cp312-cp312-win_amd64.whl
```

PESQ is an evaluation metric, not a downloadable trained enhancer and not a
speech-quality guarantee. It needs paired aligned clean reference speech.

## Remaining evidence and honest claims

Software checks cannot certify final model quality. Strict targets must actually
pass on agreed, representative noise/SNR conditions, with per-category reports.
Recorded blast audio through a laptop speaker is not a calibrated blast test.
Real impulse microphone saturation cannot be undone by an ordinary denoiser.

Still required: matched-level listening, real single-mic recordings with Windows
enhancements characterized, synchronized dual-mic captures, Pi 5 latency/power/
temperature/soak tests, physical I/O loopback, and any desired radio/PTT interface.
Physical acoustic cancellation needs error sensing and secondary-path calibration;
existing FxNLMS simulation and software bypass do not constitute that hardware.

No 17.22 ms Pi latency, <5 W power, hardware relay bypass, 140 dB AFE protection,
or complete SIH target compliance is claimed by this audit.
